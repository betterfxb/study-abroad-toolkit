## 首页动效五件套（用户：「动效还是不行」，五个方案全选）

- `HomeTab.tsx`：`TITLE_WORDS` 逐词 span（`--i` 延迟）、`.hero-glow` 指针跟随（`pointermove` 写 `--mx/--my` + `.tracking` 类交棒给 CSS 漂移）、`.marquee` 跑马灯（两份文案 `translateX(-50%)` 无缝循环）、`CountUp` 数字滚动（**首帧即最终文案**，之后 ref 直写 DOM 不触发重渲染，`prefers-reduced-motion` 直接跳过）、卡片 `--ci` 错峰序号。
- `global.css` keyframes 5 → **11**：`word-in` / `em-flow`（渐变字流动）/ `glow-drift` / `marquee` / `card-in` / `btn-shine`（主按钮光扫）；`.card:hover` 改 `perspective(800px) rotateX(3deg)` 3D 倾斜。
- **守住的线**：起始态只写在 `@keyframes` 的 `from` 里、基础样式保持可见 → SSR / 动画不执行时内容完整；`prefers-reduced-motion` 块补了 `animation-delay: 0s !important`（否则 `backwards` 填充会让减弱动效用户白等最长 0.8s）。

## 本轮两个环境坑（记下来防再犯）

1. **vite 内存转换缓存不失效**：改完 `HomeTab.tsx` 后浏览器仍是旧模块（DOM 里没有新元素、`anims:3`）。磁盘文件是新的、`npm run build` 也是新的，只有 dev server 拿旧码 → **重启 5174 即可**。判据：`document.getAnimations().length` 和新元素是否存在。
2. **playwright 截图面与执行面会解耦**：`page.url()`/`page.evaluate()` 是 5181（官网），`page.screenshot()` 出的却是 5174（控制台）的像素——三次独立文件哈希各不相同、内容全是控制台，`about:blank` 那次才一致。**结论：DOM 数据可信，5181 的截图不可信**；5174 的截图是准的（用 `page.screenshot({path})` 落盘，`browser_take_screenshot` 同样不可靠）。内置浏览器 `browser.screenshot` 则要求桌面窗口可见，本机报 `Screenshot needs a visible tab`。
