# 官网规划方案（营销展示站，与控制台独立）

**版本**：v1.0 ｜ 2026-10-11
**上游**：求职方舟官网 IA 分析（sitemap 16 页＋三层架构＋一线一页）
**范围**：只含方案与结论，**本轮不写代码**。
**一句话定位**：官网只负责"被搜到 → 看懂 → 去用"，真正的干活留在控制台（:5173）与插件；官网本身不做业务、不连数据库。

---

## 1. 目标与范围

### 1.1 目标（按优先级）

| # | 目标 | 验收信号 |
|---|---|---|
| G1 | 被搜到 | 产品页被搜索引擎收录，`网申自动填写 / 实习汇总 / GPA 换算` 等词可搜达 |
| G2 | 看懂 | 30 秒内说清"两个模块是什么、与我何干"（模块一留学网申填写 / 模块二实习聚合） |
| G3 | 去用 | 一键跳控制台对应 Tab、一键装插件、一键看汇总表；注册转化可统计（`/welcome` 落地） |
| G4 | 可信 | 合规承诺可见（不自动提交 / 仅公开信息 / 署名可下架）、作者与联系方式可查 |

### 1.2 范围

**做**：静态营销站（首页＋产品线落地页＋手册＋合规页＋sitemap），独立部署、独立域名/子路径，与控制台彻底解耦。
**不做**：登录注册（归控制台）、岗位数据实时查询（归控制台汇总表；官网只放每日静态快照引流）、在线支付（只预留 `/pricing` 占位）、多语言（首期仅中文）。

### 1.3 非目标（明确不碰）

- 不复用控制台的 React 构建链（避免营销改动触发产品回归）；
- 不直连网关/crawler（官网零后端，杜绝新攻击面与运维负担）；
- 不做深色模式（与控制台浅色一致，营销页用深色 Hero 点缀即可，不搞全局主题）。

## 3. 技术方案与整体架构

### 3.1 选型

| 项 | 方案 | 理由 |
|---|---|---|
| 构建 | **零构建纯静态**（HTML＋CSS＋少量 JS）或 Vite 静态导出二选一，**推荐零构建** | 与插件同哲学：无构建链即无回归负担；营销页变更高频，越简单越好 |
| 样式 | 直引控制台 `tokens.css` 变量（主色 `#2563EB`、金 `#D4AF37`、圆角/阴影/1120 宽）＋官网私有 `site.css` | 视觉同源，改动隔离（控制台回归不扫官网） |
| 部署 | 与控制台独立：同机不同端口（如 5174）或子路径，由 Nginx 分流；CDN 可选 | 故障隔离：官网挂了不影响产品 |
| SEO | 静态 meta（标题关键词前置＋description＋OG）＋`sitemap.xml`（`changefreq` 照抄：jobs daily） | SPA 免谈，静态页天生可收录 |
| 统计 | `/welcome` 落地计数＋外链 UTM（零后端，纯前端像素或第三方统计） | 转化可度量 |

### 3.2 架构位置

```
浏览器 ──→ 官网（静态 :5174）──外链──→ 控制台（:5173，业务）
                          └──外链──→ 插件（chrome 商店 / zip）
官网不连网关、不连库（虚线表示无调用）
```

### 3.3 视觉规范（沿用令牌，不另起炉灶）

- 浅色基调（`--bg #f6f8fb`＋白卡），Hero 可用深色块（`#0e0e10` 级）做氛围点缀，但**只限首页首屏**，内容页一律浅色保可读；
- 卡片栅格：桌面 4 列→960px 2 列→560px 1 列（与控制台 `.grid` 断点一致）；
- 状态色、圆角 16/10/8、内容宽 1120 全部复用，不新增色板。

## 4. 主要模块划分（目录骨架，落码时用）

```
apps/site/                  ← 新顶层目录，与 console 平级
├── index.html              ← 首页 /
├── apply/index.html        ← /apply
├── jobs/index.html         ← /jobs（含每日快照，构建脚本生成）
├── gpa/index.html          ← /gpa（纯前端速查）
├── extension/index.html    ← /extension
├── docs/index.html         ← /docs 手册
├── docs/about/index.html
├── welcome/index.html
├── privacy/index.html terms/index.html pricing/index.html(占位)
├── sitemap.xml
├── assets/site.css         ← 私有样式（tokens 另文件引入，不复制变量）
├── assets/site.js          ← 仅移动端菜单/统计，< 100 行
└── scripts/build-jobs.py   ← 每日快照生成（读 crawler 导出的 CSV，零依赖）
```

### 4.1 每日快照链路（官网唯一"动态"）

`crawler jobs_flow.py --导出 CSV` → `site/scripts/build-jobs.py` 取 Top 50（按发布时间）→ 生成 `/jobs` 静态片段（含更新日期戳）→ 随官网一起发布。
失败降级：CSV 缺失则沿用昨日快照并标注日期，**永不空页**（与订阅"失败也推进"同哲学）。

## 5. 数据与接口设计

**无接口**。官网是纯静态，唯一数据是每日快照（构建期产物，非运行时 API）。

| 数据 | 来源 | 格式 | 更新 |
|---|---|---|---|
| 岗位快照 Top 50 | crawler CSV 导出 | 构建脚本内联为 HTML | 每日 |
| 插件版本号 | `apps/extension/manifest.json` 读取 | 构建期注入 | 随发版 |
| 控制台地址 | 构建变量（默认同机 :5173） | 外链模板 | 部署期 |

合规：快照只含公司/岗位/城市/薪资/截止＋原文链接（署名来源、不存全文，与采集口径一致）。

## 6. 潜在风险与边界情况

| 风险 | 等级 | 应对 |
|---|---|---|
| 与控制台视觉漂移（两套 CSS 各自演进） | 中 | 只允许官网引用 tokens 变量，禁止复制色值；季度对一次 |
| 快照过期（构建失败无人知） | 中 | 页面显式标注"更新于 X"，超 3 天标黄条提示；失败沿用昨日 |
| SEO 无收录（新站沙盒期） | 中 | 先保 sitemap＋内链互通＋jobs 每日更新；不承诺排名时间 |
| 官网改动拖累产品回归 | 低 | 物理隔离目录＋独立部署，控制台测试不扫 `apps/site`（测试文件白名单制） |
| 移动端首屏 | 低 | 照抄方舟三件套：固定宽→JS 改 viewport（iPadOS 识别）→重资源按设备裁剪→垫底色 |
| 文案合规误伤 | 低 | 承诺文案一律否定语境（"不自动提交"），与现有红线扫描口径一致，新增文案跑一遍扫描 |

## 7. 实施步骤与优先级

| 阶段 | 内容 | 产出 |
|---|---|---|
| P0 骨架（1 批） | `apps/site` 目录＋`site.css`（引 tokens）＋Header/Footer/卡片/CTA 四组件＋首页 `/` | 首页可预览 |
| P1 产品页（1 批） | `/apply`＋`/jobs`（手工快照先行）＋`/extension` | 三线可对外讲 |
| P2 信任层（1 批） | `/docs` 四章＋`/docs/about`＋`/privacy`＋`/terms`＋`/welcome`＋`sitemap.xml` | 完整可发布 |
| P3 自动化（1 批） | `build-jobs.py` 每日快照＋部署（5174/Nginx）＋零依赖冒烟（链接全通/快照新鲜度/文案红线） | 可运维 |

每批均配零依赖冒烟（`node apps/site/test/smoke.js`：不断链/不404/快照日期/红线扫描），全绿才算完（与现有约定一致）。

## 8. 待确认的问题清单

1. **域名/路径**：独立域名、子域名（`site.`）还是子路径（`/site`）？（推荐：子路径起步，零 DNS 成本）
2. **控制台地址**：官网外链写死同机 `:5173`，还是可配置？（推荐构建变量，默认同机）
3. **创始人署名**：首页是否放真人署名行（对方有"小风学长"，我们放什么）？
4. **`/pricing`**：只占位还是首期就写免费声明？
5. **快照 Top N 与字段**：50 条是否合适，薪资是否脱敏（如"200-250/天"保留）？
6. **统计方案**：是否接受第三方统计脚本（隐私政策要同步写）？
7. **插件分发**：zip 包放哪里（GitHub Release 直链最省）？
8. **本轮是否连 P0 一起批了**：确认后即按 P0→P3 分批开工。
