## 1. 架构总览

### 1.1 设计原则

| 原则 | 落地方式 |
|---|---|
| 共享底座优先 | Profile 库、字段识别引擎、规则引擎、存储与调度做成独立服务，两模块共用 |
| 模块化单体起步 | 初期不拆微服务，按模块划分包结构，边界清晰；规模上来后按服务拆 |
| 合规内建 | 验证码不破解、不自动提交、采集仅公开信息，作为硬约束写进服务层 |
| 可降级 | 每个外部依赖（第三方 API / LLM / 采集源）都有一条降级链路 |
| 产出物可验证 | 每个服务可独立启动、独立测试，提供健康检查与冒烟脚本 |

### 1.2 服务划分

```
                         ┌─────────────────────┐
        ┌───────────────▶│   web-console       │  React + Vite + TS
        │                │   官网控制台         │  (资料/材料/进度/汇总表)
        │                └──────────┬──────────┘
        │                           │ HTTPS
        │                ┌──────────▼──────────┐
        │                │   api-gateway       │  NestJS
        │                │   鉴权/资料/规则/API │  (主 API)
        │                └───┬─────────────┬───┘
        │                    │             │
┌───────┴────────┐   ┌───────▼──────┐  ┌───▼─────────────────┐
│  extension     │   │  PostgreSQL  │  │ intelligence-service│  FastAPI
│  Chrome MV3    │   │  + Redis     │  │ 字段匹配/文书/GPA换算│  (AI 服务)
│  插件          │   └───────┬──────┘  └───┬─────────────────┘
└───────┬────────┘           │             │
        │ HTTPS/WSS          │             │
        └────────────────────┴─────────────┘
                             │
                    ┌────────▼─────────┐
                    │ crawler-service  │  FastAPI + Celery
                    │ 采集/解析/去重    │
                    └────────┬─────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        第三方数据API    招聘平台/官网    自建RSS
```

| 服务 | 技术栈 | 职责 | 对应模块 |
|---|---|---|---|
| `web-console` | React 18 + Vite + TypeScript + UnoCSS | 官网控制台：资料管理、材料库、汇总表、进度跟踪 | 共用 |
| `extension` | Chrome MV3 + TypeScript + Vite(CRXJS) | 页面感知、字段抽取、填充执行、步骤控制 | 模块一 |
| `api-gateway` | NestJS + TypeScript | 鉴权、Profile、材料、规则、对外 API | 共用 |
| `intelligence-service` | Python + FastAPI | 字段语义匹配、GPA 换算、文书微调 | 模块一（+模块二抽取复用 LLM 客户端） |
| `crawler-service` | Python + FastAPI + Celery | 多源采集、正文抽取、LLM 结构化、去重 | 模块二 |
| `scheduler` | Celery Beat | 定时任务编排、频控、源健康度调度 | 模块二 |

> **拆分说明**：`intelligence-service` 与 `crawler-service` 均为 Python，初期可同进程不同包，共用 `llm_client`、`db` 等基础库；待 QPS 上来再物理拆分。

## 2. 共享底座

| 组件 | 说明 | 复用方 |
|---|---|---|
| Profile 库 | 用户结构化资料（JSONB）+ 材料文件 + 简历版本 | 模块一 |
| 字段识别引擎 | 多信号（label/aria/name/placeholder/邻近文本）+ LLM 语义匹配 | 模块一 |
| 规则引擎 | 字段词典 + 映射规则 + 优先级决策 | 模块一 |
| 存储与调度 | PostgreSQL + Redis + 对象存储 + 任务队列 | 两模块 |
| LLM 客户端 | 统一封装（多模型路由、重试、降级、成本计量） | 两模块 |
| 审计与合规 | 操作审计、频控、下架通道 | 两模块 |

**LLM 统一客户端设计要点**（沿用你既有的多模型接入思路）：
- 统一接口 `LLMClient.complete(task, payload)`，按 task 路由到不同模型。
- 动态路由：字段匹配走快模型，文书微调走强模型，抽取走性价比模型。
- 失败自动降级：主模型超时/报错 → 备用模型 → 规则兜底。
- 成本计量：按调用方/任务类型埋点，便于后续配额。

## 3. 模块一 · 留学网申填写 数据流

```
用户在申请页 → 插件 PageSense 判定为表单页 → 激活悬浮按钮
   ↓
FieldExtractor 扫描当前步骤 DOM → 产出字段清单 + 语义候选
   ↓ HTTPS
api-gateway → intelligence-service
   ├─ AdapterRouter 识别平台/院校（ApplyWeb / Liaison / Slate / 自研）
   ├─ FieldMatcher 三级匹配：Embedding 词典检索 → LLM 语义匹配 → 规则兜底
   └─ 特殊处理器：GPA 换算、语言成绩映射、日期/地址格式化
   ↓ 返回填充指令（fieldSelector + value + confidence + handler）
Filler 按字段类型差异化写入
   ├─ 受控组件：native setter + input/change/blur
   ├─ 下拉/级联：真实点击序列
   ├─ 日期：日期选择器交互
   ├─ 富文本：innerHTML + 事件派发
   └─ 附件：DataTransfer 构造 FileList + drop/change
   ↓
Validator 回读校验 → StepController 触发 Save & Continue → 下一步重扫
   ↓
填写日志上报 → 未填/低置信字段汇总 → 用户人工复核 → 用户自行提交
```

**关键设计点**

1. **步骤控制器状态机**：`IDLE → SCANNING → FILLING → SAVING → NEXT_STEP → DONE`；每步进入前强制重扫 DOM（适配 SPA 增量渲染与动态字段）。
2. **置信度分级**：`≥0.9` 自动填；`0.6–0.9` 填 + 高亮提示复核；`<0.6` 不填，列入待办。
3. **草稿回填**：优先读服务端草稿态，避免重复覆盖用户已改内容。
4. **合规闸门**：检测到 reCAPTCHA / hCaptcha / Cloudflare Turnstile 或"提交"按钮 → 立即暂停并提示人工，**不执行提交动作**。
5. **敏感字段**：护照号、成绩单等单独加密，默认不上传云端（本地优先）。

## 4. 模块二 · 实习信息爬取 数据流

```
scheduler（Celery Beat）
   ↓ 按源频控下发任务
crawler-service 采集器（多源适配器）
   ├─ SourceAdapter: thirdparty_api / rss / job_platform / company_site
   ├─ 代理池 + UA 池 + 随机间隔（合规前提下的低频）
   └─ 原始数据落 raw_articles
   ↓
解析层
   ├─ 正文抽取（trafilatura / readability）
   └─ LLM 结构化抽取 → 岗位字段
   ↓
处理层
   ├─ 去重（三级：URL 唯一键 / SimHash 指纹 / 跨源对齐）
   ├─ 字段标准化（城市、薪资、学历、时间）
   └─ 分类打标 + 置信度阈值过滤
   ↓
存储层：articles / jobs / dedup_index → 对象存储（封面图）
   ↓
服务层：搜索/筛选 API · 订阅推送 · 后台管理 · 降级开关
   ↓
监控层：任务监控 · 失败告警 · 频控看板 · 质量抽检
```

**关键设计点**

1. **源适配器插件化**：新增源只需实现 `SourceAdapter` 接口（`fetch()` / `parse()` / `health_check()`），不改核心链路。
2. **源健康度评分**：按成功率、时延、字段完整率打分，低于阈值自动降权并触发告警。
3. **降级链路**：`L0 全自动多源 → L1 切源（自建RSS+官网）→ L2 半自动（运营转发统一入口）→ L3 人工汇总表`；降级开关由后台一键切换。
4. **合规内建**：`robots` 检查、频控令牌桶、仅存摘要+原文链接、来源署名、权利人下架接口。
5. **幂等**：采集任务以 `source_id + 时间窗` 为幂等键；重复执行不产生脏数据。

## 5. 部署拓扑

### 5.1 起步（Docker Compose，单机）

| 容器 | 端口 | 说明 |
|---|---|---|
| `console` | 5173 | 控制台前端（生产由 Nginx 托管） |
| `api` | 8080 | NestJS 主 API |
| `intel` | 8090 | FastAPI AI 服务 |
| `crawler` | 8100 | FastAPI 采集服务 |
| `worker` | — | Celery Worker |
| `beat` | — | Celery Beat |
| `postgres` | 5432 | PostgreSQL 16 |
| `redis` | 6379 | Redis 7 |
| `minio` | 9000 | S3 兼容对象存储 |

> 端口规划与你既有习惯一致：Node 主服务 8080、Python 服务 8090 起。

### 5.2 规模化（K8s）

- 无状态服务（api / intel / crawler / worker）水平扩容。
- PostgreSQL 主从 + 读写分离；Redis 哨兵；对象存储用云 OSS。
- 采集侧独立节点池 + 出口 IP 池，与业务节点隔离。

## 6. 关键横切设计

| 主题 | 方案 |
|---|---|
| 鉴权 | 控制台用 JWT（Access + Refresh）；插件用长期 Token + 设备指纹，支持吊销 |
| 插件↔服务端 | HTTPS（REST）为主，WebSocket 用于长任务进度推送 |
| 加密 | 传输 TLS；Profile 敏感字段 AES-256-GCM；密钥服务端托管，定期轮换 |
| 幂等 | 写接口带 `Idempotency-Key`；采集任务用业务幂等键 |
| 重试 | LLM/采集统一指数退避重试（3 次），超限进死信队列 |
| 限流 | 网关层按用户/IP 令牌桶；采集层按源独立令牌桶 |
| 灰度 | 插件版本按用户白名单灰度；服务端特性开关（Feature Flag） |
| 可观测 | 结构化日志 + Prometheus 指标 + Sentry 异常 + 关键链路 TraceID |
| 配置 | 环境变量 + 配置中心；敏感配置走密钥管理，不入库不入仓 |
