# 03 · 接口契约

**版本**：v1.0 ｜ 2026-10-09
**风格**：RESTful + JSON；内部服务间可用 gRPC（后期）
**Base URL**：`https://api.<domain>/api/v1`（业务）｜ `/ext/v1`（插件专用）
**鉴权**：控制台 `Authorization: Bearer <JWT>`；插件 `X-Ext-Token: <token>`
**通用响应**

```json
{ "code": 0, "message": "ok", "data": {}, "trace_id": "..." }
```

`code` 非 0 表示业务错误。写接口需带 `Idempotency-Key`。

**定时执行**

订阅可选配 `schedule` 表达式，由调度器按周期自动跑匹配与推送（不配置则只支持手动「立即执行」）。

| 表达式 | 语义 |
|---|---|
| `''` | 不自动执行（默认） |
| `hourly` | 每小时整点 |
| `daily@HH:MM` | 每天 HH:MM（按 `SCHEDULER_TZ_OFFSET`，默认东八区 +480） |
| `weekly@MO,WE,FR@HH:MM` | 每周指定星期几的 HH:MM（`SU MO TU WE TH FR SA`） |
| `every:Nm` | 每 N 分钟（1..1440） |
| `every:Nh` | 每 N 小时（1..168） |

> 表达式非法 → `1001`。解析与计算为纯函数（`apps/api/src/common/schedule.ts`），零第三方依赖。
> 调度器实现于 `apps/api/src/scheduler/`，每 `SCHEDULER_INTERVAL_MS`（默认 60s）扫描一次，
> 只取「启用中 + 有表达式 + `next_run_at` 已到点」的订阅（走 `idx_subscriptions_due` 索引）。
> **失败也会推进 `next_run_at`**，避免上游不可用时形成热循环；单条失败不影响同轮其它订阅。
> 开关：`SCHEDULER_ENABLED=0` 关闭；`SCHEDULER_TZ_OFFSET` 调整时区。

**多实例互斥**：候选查询与执行之间由 `subscriptions.claimDue()` 用**单条条件 UPDATE 原子抢占**
（仍启用且有表达式 + 仍到期 + 无锁或锁已陈旧），只有抢到的实例才执行，**不引入 Redis**。
`locked_at` 早于 `SCHEDULER_LOCK_TTL_MS`（默认 5min）视为持有者已崩溃，可被其它实例接管；
实例正常退出时释放自己持有的锁。因此同一订阅在多实例部署下**只会被执行一次**。

```jsonc
// 订阅对象新增字段（GET /subscriptions 等）
{
  "schedule": "daily@09:00",
  "schedule_text": "每天 09:00",
  "next_run_at": "2026-10-10T01:00:00.000Z"
}
```

```jsonc
// GET /scheduler/status → res.data
{
  "enabled": true,
  "instance_id": "gateway-1",          // 实例标识（SCHEDULER_INSTANCE_ID，缺省 hostname:pid:随机）
  "interval_ms": 60000,
  "lock_ttl_ms": 300000,               // 抢占锁 TTL
  "tz_offset_minutes": 480,
  "scheduled": 12, "due": 0, "next_run_at": "2026-10-10T01:00:00.000Z",
  "locked": 0,                         // 当前被抢占且未过期的订阅数
  "running": false,
  "ticks": 143,                        // 累计完成的扫描轮次
  "busy_ticks": 0,                     // 因上一轮未结束而跳过的轮次（单飞保护）
  // ↓ 累计计数器：多实例互斥判定必须看累计值（last_result 只保留最近一轮，逐轮采样会漏）
  "scanned_total": 156, "ran_total": 151, "failed_total": 5, "skipped_total": 4,
  "last_tick_at": "2026-10-09T08:54:54.383Z",
  "last_result": {
    "at": "...", "scanned": 1, "ran": 1, "failed": 0, "skipped": 0, "busy": false, "items": []
  }
}
```

> `POST /scheduler/tick` 返回同一个 `TickResult` 结构，其中 `skipped` 表示「被其它实例抢占
> （或已被推进）而让出」的数量，`busy: true` 表示上一轮尚未结束、本轮直接跳过。

## 8. 错误码

| code | 含义 | 处理建议 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 参数校验失败 | 检查入参 |
| 1002 | 未认证 / token 失效 | 刷新或重新登录 |

## 9. 契约约定

1. **分页**：统一 `page`（从 1 起）+ `size`（默认 20，最大 200），响应含 `total`。
2. **排序**：`sort=field:asc|desc`，多字段逗号分隔。
3. **时间**：一律 ISO 8601 UTC（`2026-10-09T05:36:30Z`）。
4. **幂等**：`POST` 写接口需带 `Idempotency-Key`（UUID），24h 内同键返回首次结果。
5. **版本**：路径带版本号；破坏性变更升版本，旧版本保留至少 1 个大版本周期。
6. **限流**：响应头返回 `X-RateLimit-Limit / -Remaining / -Reset`。
