## 2. PoC 运行方式

```bash
cd apps/crawler

# 离线样例（零外部依赖，验证链路）
python scripts/poc.py --sources config/poc_sources.json --repeat 2

# 接入真实 RSS 源
python scripts/poc.py --adapter rss --feed-url https://example.com/feed.xml

# 开启 LLM 结构化（需配置 LLM_API_KEY）
python scripts/poc.py --sources config/poc_sources.json --use-llm
```

产出：控制台摘要 + `docs/03-PoC/poc-report-<时间戳>.md` 与 `.json`。

源清单在 `apps/crawler/config/poc_sources.json`，默认只开离线样例源，
其余（第三方 API / 招聘平台 / RSS / 官网）填好配置后把 `enabled` 改为 `true` 即可。

## 3. 已实现的 PoC 能力

### 3.1 采集层

| 能力 | 实现 | 验证 |
|---|---|---|
| 多源适配器插件化 | `SourceAdapter` + `@register`，5 个适配器 | ✅ 注册表测试通过 |
| 统一 HTTP 客户端 | `HttpClient`：robots 检查 + 按域令牌桶 + 重试 + UA/代理 | ✅ 6 项测试通过 |
| 传输层可注入 | `transport` 参数，单测不发真实请求 | ✅ |
| 频控 | 按域名独立令牌桶 + 随机抖动 | ✅ |
| 限流识别 | 429/403/503 标记 `rate_limited` 并退避重试 | ✅ |

### 3.2 合规层（硬约束）

| 能力 | 实现 | 验证 |
|---|---|---|
| robots.txt 遵守 | `RobotsCache`：抓取 + 缓存 + `can_fetch` | ✅ 允许/禁止路径均正确 |
| robots 不可达策略 | `allow_on_error` 可配（默认放行，严格模式拒绝） | ✅ 两种模式均测 |
| 域名白名单/禁采名单 | `DomainPolicy` | ✅ |
| 权利人下架 | `TakedownRegistry`（URL / 域名级） | ✅ |
| 合规总闸 | `ComplianceGuard.check()` 串联三项检查 | ✅ |
| 不存全文 | `CRAWLER_STORE_FULLTEXT=false`，仅存摘要 + 原文链接 | ✅ 默认关闭 |

### 3.3 处理层

| 能力 | 实现 |
|---|---|
| 三级去重 | URL 唯一键 → 指纹（文章/岗位）→ SimHash 近似判重 |
| 字段标准化 | 城市别名、薪资区间（含 `5k-8k/月`）、学历、日期（`11月30日`）、投递方式 |
| 结构化抽取 | LLM 优先，不可用时降级**规则抽取**，链路不断 |
| 置信度推导 | 按关键字段填充度计算（`0.35 + 0.08×字段数`，上限 0.90） |

### 3.4 降级链路

| 场景 | 判定 | 验证 |
|---|---|---|
| 主源健康 | 保持 L0 全自动 | ✅ |
| 主源挂、兜底源健康 | → L1 切源 | ✅ |
| 自动源全挂、人工有投递 | → L2 半自动 | ✅ |
| 全部无产出 | → L3 人工汇总 | ✅ |
| 源恢复 | 逐级回升（每次 1 档，防抖动） | ✅ |

### 3.5 管理接口（15 个）

```
GET    /health                            健康检查
GET    /internal/health                   内部健康检查
GET    /internal/adapters                 已注册适配器
POST   /internal/crawl/run                执行一次采集（连通性验证）
POST   /internal/extract                  正文 → 岗位结构化
POST   /internal/dedup/check              SimHash 查重
GET    /admin/adapters                    适配器清单
GET    /admin/degrade                     当前降级层级
POST   /admin/degrade                     手动切换降级层级
POST   /admin/degrade/evaluate            按健康度自动评估层级
GET    /admin/sources                     源列表
POST   /admin/sources                     新增源
PATCH  /admin/sources/{id}                修改源
POST   /admin/sources/{id}/run            手动触发采集
GET    /admin/sources/{id}/health         源健康度趋势
GET    /admin/tasks                       任务列表
```

数据库不可用时，管理接口优雅返回 **503**（而非 500），不影响采集链路可用性。

## 5. 开发过程中修掉的关键缺陷

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | `岗位职责：xxx` 被误判为「岗位」字段 | 单篇文章被拆成多条，产生废数据 | 标签匹配改为**行首锚定 + 后接分隔符** |
| 2 | 规则抽取置信度写死 0.5 | 「低置信度占比」指标失效（恒为 100%） | 改为按关键字段填充度推导 |
| 3 | SimHash 阈值 3 对中文过严 | 同文改写被误判为不同文 | 阈值调至 8（实测近似 5~8、无关 30+） |
| 4 | 薪资区间 `5k-8k/月` 匹配失败 | 薪资字段丢失 | 正则允许单位出现在区间两端 |
| 5 | 日期 `11月30日` 解析失败 | 截止日期丢失 | 补充 `月/日` 日期模式 |
